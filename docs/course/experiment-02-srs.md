## 1. 引言

### 1.1 目的

本文定义 NoteAgent 在本次课程设计范围内的用户角色、业务边界、功能需求、非功能需求及验收方法，为后续 UML 建模、概要设计、详细设计和测试提供依据。需求是目标行为，文中列出的验收方法不代表已经通过测试。

### 1.2 背景与范围

NoteAgent 是已有的个人笔记项目。学习者可以通过聊天提出笔记整理请求，在确认草稿后保存为 Markdown 文件，也可以直接管理文件并检索旧笔记。本次规格聚焦现有 V1 文本闭环；网页采集、音视频处理、多用户账号和管理员后台不属于本次范围。

### 1.3 术语

| 术语 | 定义 |
| --- | --- |
| 学习者 | 使用系统记录、整理和检索个人学习笔记的人；不等同于系统账号。 |
| 本地维护者 | 负责本地部署、配置和排错的人；不是具备独立后台权限的管理员账号。 |
| 草稿 | 系统提出、尚待学习者确认的笔记创建或修改内容。 |
| 正式笔记 | 学习者直接保存或确认草稿后写入 `notes/` 的 Markdown 文件。 |
| 索引 | 为笔记检索生成的数据；其状态与笔记文件保存状态分别判断。 |
| 来源 | 检索答案所依据的笔记文件及其片段位置。 |

### 1.4 预期读者、参考资料与约定

预期读者为课程教师、课程设计者及后续实现和测试人员。调研方法与候选需求见 [模拟需求调研记录](experiment-02-research.md)；项目现状参考 [产品与业务架构](../product/business-architecture.md)、[聊天工具契约](../architecture/chat-tools.md)、[前端说明](../architecture/frontend.md)和对应代码。本文以 `FR-xx` 标识功能需求，以 `NFR-xx` 标识非功能需求；“必须”表示本次范围内的验收要求，“建议”表示后续可讨论项。优先级 P0 为核心闭环，P1 为辅助操作。

## 2. 项目概述

### 2.1 系统概述与业务流程

学习者输入问题或整理请求。普通问题由系统回答；明确的笔记整理请求产生待审草稿。学习者查看草稿后选择确认或拒绝：确认后保存正式笔记并更新检索索引；拒绝不修改正式笔记。学习者也可在 Documents 界面直接编辑笔记。之后通过检索查看旧笔记及答案来源。

### 2.2 用户与权限边界

| 用户类别 | 主要任务 | 本次权限边界 |
| --- | --- | --- |
| 学习者 | 聊天、审核草稿、管理笔记、检索笔记 | 本次为个人本地使用场景，不定义账号与细粒度权限。 |
| 本地维护者 | 部署、配置、查看运行错误与日志 | 通过本地运行环境完成，不定义独立管理员界面。 |

### 2.3 运行环境与约束

项目使用 Python Web 服务、Markdown 文件、会话数据库、检索索引和外部大模型接口。具体版本与启动步骤以仓库 `README.md`、`pyproject.toml` 和部署配置为准。模型服务或检索索引不可用时，系统必须给出可区分的错误；不能将失败伪装成成功或“没有笔记”。本次不承诺离线大模型能力。

## 3. 功能需求

### 3.1 聊天与会话

**FR-01 会话消息。** 学习者输入非空文本并发送时，系统必须创建或沿用会话，显示本次消息及最终回复，并将可恢复的会话记录持久化。输入为空时不得发送；模型调用失败时显示失败，不得显示伪造回复。验收：发送一条消息后重新打开会话可见该消息与成功取得的回复；空输入与模拟模型错误分别验证。优先级 P0。来源：Q2、现有 `POST /chat` 与会话接口。

**FR-08 会话管理。** 学习者必须能够列出、打开、重命名和删除会话。删除会话前应明确确认；删除会话不应删除已保存的正式笔记。验收：分别执行四项操作，检查列表和笔记文件状态。优先级 P1。来源：现有会话接口。

### 3.2 草稿与人工确认

**FR-02 草稿提出。** 学习者明确要求创建、追加、替换或删除笔记，且模型服务成功生成提案时，系统必须展示包含目标文件、操作类型和内容的待审草稿；生成草稿不得立即修改正式笔记。普通问答不得自动保存为笔记。验收：比较提案前后的目标文件，确认内容不变；普通问答不产生待审草稿。优先级 P0。来源：Q3、I1、现有 `propose_note` 流程。

**FR-03 草稿审核。** 学习者确认待审草稿后，系统必须按草稿的操作类型执行对应笔记变更；学习者拒绝时，正式笔记保持不变。写入失败时必须报告失败并保留可恢复的待审草稿。验收：分别测试确认、拒绝与模拟写入失败，检查文件内容和草稿状态。优先级 P0。来源：Q3、Q5、I1、现有 `POST /chat/review` 流程。

### 3.3 笔记管理

**FR-04 Markdown 笔记操作。** 学习者必须能够在 Documents 界面创建、读取、编辑并删除 `notes/` 范围内的 Markdown 笔记。保存成功后重新打开应显示最新内容；删除前应要求确认；无效路径不得访问目录外文件。验收：执行创建、编辑、重开、取消删除、确认删除和非法路径用例。优先级 P0。来源：Q1、I3、现有笔记接口。

**FR-05 笔记分类。** 学习者必须能够创建一层文件夹、重命名文件夹，并将笔记移入文件夹或移回根目录。目标路径冲突或不合法时，系统必须提示失败且保留原文件。验收：执行创建、重命名、移动、移回和目标冲突用例，检查文件路径与内容。优先级 P1。来源：Q2、现有 Documents 操作。

### 3.4 检索与索引

**FR-06 检索与来源。** 学习者询问已保存的学习内容时，系统必须检索可用笔记，并在使用检索片段回答时提供可定位到笔记的来源。无命中时应说明未找到依据；检索执行错误应单独报告。验收：准备可检索笔记，分别验证命中、无命中与模拟检索错误。优先级 P0。来源：Q4、I2、现有检索流程。

**FR-07 索引状态。** 正式笔记创建、编辑或移动后，系统必须尝试更新对应检索索引；删除笔记后必须尝试移除对应索引。已保存笔记的索引更新失败时，Documents 界面必须显示未索引状态并允许手动重试；删除索引失败时必须显示错误，不得报告完整成功。验收：分别模拟更新、删除索引的成功与失败，核对笔记文件、索引状态和提示；恢复后再次检索不应返回旧内容。优先级 P0。来源：Q5、I3、现有笔记与检索接口。

现状差异：当前 [`notes/router.py`](../../src/noteagent/notes/router.py) 在删除笔记或移动笔记后清理旧索引失败时仅记录日志，HTTP 操作仍可能返回成功。FR-07 的该异常分支属于后续待实现和待测试要求，不视为当前已满足。

## 4. 非功能需求

### 4.1 性能与可用性

**NFR-04 本地笔记列表响应。** 在课程测试环境中准备 100 篇不超过 20 KiB 的 Markdown 笔记，连续请求 `GET /notes` 20 次；不含服务首次启动时间，95% 的请求应在 2 秒内返回完整列表。该阈值为模拟调研后的待验证目标，实验测试前可根据真实使用环境修订。验收：记录环境、请求耗时与通过比例。来源：Q2。

**NFR-05 界面反馈。** 笔记有未保存修改时，学习者切换笔记或离开编辑界面必须收到明确提示；保存、索引等操作失败时必须显示失败状态。验收：手工执行未保存切换和模拟失败场景。来源：Q5、I3。

### 4.2 安全与数据完整性

**NFR-01 人工确认边界。** 除学习者在 Documents 界面直接保存外，模型提出的草稿在学习者确认前不得更改任何正式笔记；拒绝后也不得更改。验收：比较操作前后文件哈希。来源：Q3、I1。

**NFR-02 文件路径约束。** 所有笔记文件操作必须限制在 `notes/` 内，拒绝绝对路径、`..` 路径穿越和非 Markdown 笔记文件名。验收：输入上述非法路径，确认请求失败且目录外文件未变。来源：现有文件仓库约束。

**NFR-03 失败可辨认。** 笔记保存失败、检索错误和检索无命中必须显示为不同结果；索引失败时不得宣称索引成功。验收：分别注入四类状态，核对接口返回与界面提示。来源：Q5、I3、I4。

### 4.3 运行日志

**NFR-06 故障定位与密钥保护。** 模型调用、笔记写入和索引失败时，运行日志必须包含时间、操作类型和可定位的错误上下文；日志不得记录完整 API Key。验收：模拟三类失败并检查日志，搜索所用测试密钥全文不得命中。来源：I4。

## 5. 外部接口说明

| 接口类别 | 本次范围内的接口 | 输入与输出约束 |
| --- | --- | --- |
| 用户界面 | Chat 与 Documents 页面 | 提供聊天、草稿审核、笔记编辑、检索来源与错误提示。 |
| HTTP 接口 | `/chat`、`/chat/review`、`/conversations`、`/notes` 及相关资源路径 | 使用项目现有 JSON 或事件流契约；错误应保持可辨认。 |
| 文件接口 | `notes/` 下的 `.md` 文件 | 仅使用仓库允许的相对路径；写入和删除必须遵循用户操作或确认。 |
| 外部服务 | 大模型 API、会话数据库、检索索引 | 服务不可用时返回明确失败；不得伪造回答或索引成功。 |

具体字段和状态码以项目现有接口模型及后续详细设计为准；本规格不新增账号、管理员或第三方采集接口。

## 6. 其他需求

课程实验使用模拟调研资料，不收集真实个人信息。测试数据应采用虚构笔记与测试密钥，不把真实密钥、数据库文件或个人笔记提交到公开仓库。实验报告需要保存需求到测试的对应关系，并注明尚未执行的验收项。

## 7. 可能影响需求的因素

真实学习者访谈可能改变功能优先级；外部大模型的可用性与费用可能影响聊天体验；笔记规模增长可能改变性能阈值；未来若加入多用户账号或网页、音视频采集，需要重新定义角色、权限、数据边界与验收要求。这些变化不自动进入本次范围。
